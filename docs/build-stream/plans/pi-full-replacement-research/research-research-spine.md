## 3. Orchestrator mechanics

**Work cycle order** (`_work_cycle` `agent_lifecycle.py:228-368`):
1. Project-scoped steering drained FIRST (`_process_project_steering :370`, checks `project_ids_with_queued_steering` `app/core/steering.py:254`) — if any, execute them and end the cycle (`:411`).
2. Resource governor gate (`:238-244`), LLM availability gate via `compute_registry.has_available_node()` (`:247-254`).
3. A2A inbox (`_process_a2a_inbox :562`, 3 unread max per cycle `:567`).
4. `_pick_next_task :1076`: priority `critical>high>medium>low` (`:1086-1092`), tasks assigned to this agent, lock-aware (`:1103-1107`), backoff-aware (`_is_in_backoff :552`); unassigned fallback **only for `istara-main`** (`:1117-1131`).
5. Execute under `governor.register_agent` + `steering_manager.mark_working/mark_idle` (`:297-306`).
6. Queue-depth broadcast + interval adaptation (`:309-349`).
7. Follow-up queue drained only when pipeline is empty ("pi-mono followUpQueue pattern", `:354-366`).

**A2A message types dispatched** (`_process_a2a_inbox` `agent_lifecycle.py:577-584`):

| message_type | Handler | Line |
|---|---|---|
| `collaboration_request` | `_handle_collaboration` — multi-turn thread via `context_id`, capability card + RAG, one LLM call, replies `collaboration_response`, appends to `task.agent_notes` | `:772-886` |
| `debate_request` | `_handle_debate` — critical-review LLM call, replies `debate_response` | `:968-1029` |
| `delegate` | `_handle_delegate` — JSON content subtypes: `pi_delegate` (`:688-707`) and `mece_report_request` (`:709-768`, MECE regen + synthesis trigger + `report` reply) | `:678-770` |
| `a2a_task` | `_handle_a2a_task` — public `tasks/send` envelope → Pi delegation | `:591-627` |

Producer side: `_trigger_mece_reporting :1031` sends `delegate`; `_initiate_debate :888` sends `debate_request`. Steering producers: `app/api/routes/steering.py:154` (steer), `:189` (follow_up), `:220` (abort).

**Existing Pi delegation hook**: `_run_and_persist_pi_delegation` `agent_lifecycle.py:629-676` → gate `pi_replacement_requested` (`app/core/pi_replacement.py:35-46`; engine values `pi|pi-candidate|pi-replacement|deepseek-pi` `:25`) → `run_pi_delegation` (`app/core/pi_runtime/seams.py:142-181`) → `PiExecutionService.run_delegation` with `DELEGATION_SYSTEM_PROMPT` (governance clause `seams.py:29-46`) and tool executor `_authority_tool_executor` (`:71-76`, canonical `execute_tool`); fail-closed on resolver error or non-`success` terminal (`:168-180`); reply persisted as A2A `response` (`agent_lifecycle.py:655-676`). Sibling seams: `build_pi_channel_reply :79` (channel turns) and `run_pi_governed_autoresearch :184` (single read-only hypothesis turn).

**What the Pi hook does NOT cover**: the entire task loop — `_pick_next_task`/`_execute_task` and everything beneath (L1 ReAct, L2 planner, L3 DAG executor, L4 skill+validation, L4b debate, L5 reflection, L6 self-check, L7 improvement); steering (L10) and follow-up execution; `collaboration_request`/`debate_request`/`mece_report_request` handlers; findings storage/research-spine persistence; compaction (L9). Only explicitly Pi-selected A2A envelopes (`a2a_task` with Pi metadata, or `delegate` with `type=pi_delegate`) reach Pi.

## 4. Migration notes (Pi ownership per loop)

| Loop | Fit | Justification |
|------|-----|---------------|
| L1 General ReAct | (ii) one session per task | Pi's agent loop natively owns tool iteration; expose `OPENAI_TOOLS` + `run_skill` via `_authority_tool_executor`; the 5-iteration cap becomes a turn budget; terminal verification stays Istara-side. |
| L2 Planner | (i) one session per step — **contingent on (iii)** | Single strict-JSON-schema call; if `PiExecutionService` turns cannot carry `response_format` (current seams are text-turn shaped, `seams.py:142`), this needs an engine API extension. |
| L3 Step executor | (ii) per task with followUp for serial plans; (iii) for parallelism | Sequential steps map to followUp turns carrying past-step results; the `asyncio.gather` DAG-parallel branch (`agent_research.py:577`) has no analogue in a single serial session — needs multi-session fan-out engine API or dropping parallelism. |
| L4 Skill exec + ensemble | (ii) for the skill call (as a `run_skill` tool inside the task session); (iii) for validation | `self_moa/dual_run/full_ensemble/debate_rounds` are multi-sample/multi-model consensus calls — needs an engine sampling/ensemble API; per-skill 600s timeout must map to turn timeout. |
| L4b A2A debate | (i) one session per exchange | Request/critique/synthesize are three independent single calls; `history` param of `run_delegation` already fits the thread. |
| L5 Reflection verifier | (i) one session per step | One judge call; regex-JSON should be upgraded to schema output — same response_format dependency as L2. |
| L6 self_check `verify_claim` | (i) one session per claim | Stateless single call with deterministic line-format parse; trivially per-step; batch `check_findings` is just a loop. |
| L7 Skill-improvement reflection | (i) one session per step | Low-frequency single free-text call; proposal/governance persistence stays Istara-side. |
| L8 Memento (ReasoningBank) | none — no Pi session | No LLM involved (`reasoning_bank.py:175-235` is templated); keep as Istara persistence hook fired from turn results. |
| L9 Compaction | (i) one session per batch | Stateless map-reduce summarization; high-volume background — could also stay on local ollama; no tool use, no state. |
| L10 Steering executor | (ii) — natural fit | `steering.py` already mirrors pi-mono's PendingMessageQueue (docstring `:1-39`); a Pi per-task session with native steering/followUp injection replaces the keyword-skill routing entirely. |
| A2A collaboration | (i) per inbound message | Single reply turn; thread history maps to `run_delegation(history=...)` (`seams.py:148`). |

**Cross-cutting gap — abort**: `steering_manager.abort` (`steering.py:353-374`) only clears queues and flips `is_working`; nothing cancels an in-flight `skill.execute`/`ollama.chat` (no abort check inside L1-L4). A Pi migration gets true mid-turn abort only if the engine exposes turn cancellation — that is a new capability, not parity.
