Fusion: why the best match scores "1.6%"

Reciprocal Rank Fusion reads ranks, not scores. A chunk ranked r in a list contributes weight / (60 + r). The fused value is the right tool for ordering, but it is not a relevance probability. Before this work, that value overwrote r.score. The UI then rendered it as a percentage, and the model saw it as relevance: 0.01. re-verified

The Memory view now shows a result's rank (#1, #2…) instead of the fused value as a percentage. Scenario 85 asserts that every badge matches #n. The model-facing label still prints the fused value, which is listed as open under F12.

The context budget: 409 tokens for evidence

BudgetCoordinator.allocate gives retrieved evidence min(5% of the window, 4,000) tokens. At the default window of 8,192 tokens, that is 409 tokens, about 1,600 characters. Top-5 retrieval can return 6,000 characters. Compression therefore decides which evidence the model sees, and before this work the UI cited every retrieved source regardless. re-verified

Identity min(0.3·ctx, 3000) · RAG min(0.05·ctx, 4000) · reply max(512, 0.05·ctx) · buffer 5% · history gets the rest. Compression ratios also depend on host RAM (compute_surplus_level), so the same question can compress differently on two machines.

The evidence graph: provenance, not knowledge

Istara's "GraphRAG" is a table of typed edges recording where every research claim came from: research_evidence_edges. That is valuable for an auditable research spine, and it is a different thing from a knowledge graph. Traceability is a fixed sequence of SQL filters: reports → findings → tasks → code applications → coding runs → gate assessments → decisions → edges. There is no traversal algorithm, and nothing "backfills" graph results with hybrid hits, despite the edge metadata's graph_policy name.

Measured gap: no production producer of a retrieved chunk sets evidence_unit_id, and the helper that would supply it (retrieval_metadata_for_unit) has no callers. So every chunk the retriever returns carries empty evidence handles, and keyword hits are labelled missing_provenance. The graph and the retriever do not meet.

Agents, and the loops that let them learn

Retrieval feeds the agents, and the agents write back. That write-back is where the governance contract applies: AGENTS.md forbids mutating global state from project-scoped evidence, and forbids learning strong positive signals from raw tool success. How it is measured today, and what that misses

Istara has many harnesses. Almost all of them check presence: a view renders, an endpoint answers, a result list is non-empty. None measures whether the results are relevant.

The QA lane cannot measure vectors. The container provider stub returns 8-dimensional vectors derived from a SHA-256 of the text re-verified, so vector similarity is unrelated to meaning. Any retrieval check in that lane measures BM25 and the plumbing. That is exactly where this round's defects were, but it is not a vector evaluation.

What to measure next

Istara generates answers, so unlike a context-only tool, answer-level RAG evaluation applies here. The order below goes from cheapest and most decisive to most expensive.

1 · A relevance set (qrels)

Take a synthetic research corpus (the seeder's slice), write 50–100 researcher questions, and pool the top 10 from BM25, vector and hybrid for graded relevance labels, TREC-style. Report Recall@k, nDCG@10 and MRR with bootstrap confidence intervals. This one set replaces the autoresearch pseudo-score (F3) as the tuning objective.

2 · Fusion and chunking ablations

With qrels in hand, sweep the 0.7/0.3 weights, k = 60, the chunk size and overlap, re-indexing per setting. The current loop mutates the chunk size without re-chunking, so it measures nothing. Compare with a paired randomization test (Smucker et al., CIKM 2007).

3 · Budget recall

Of the relevant chunks retrieved, how many survive the 409-token compression? Measure recall as a function of the context window. This is the number that decides whether the model ever sees the evidence.

4 · Answer faithfulness

RAGAS-style faithfulness and context precision (Es et al., EACL 2024), or ARES with a small human-labelled calibration set (Saad-Falcon et al., NAACL 2024). This needs the owner-gated live lane. Validate the judge against human labels before trusting it, and never let the judge be the model under test.

5 · Provenance coverage

The share of retrieved chunks carrying an evidence_unit_id. It is 0% today. Once the retriever and the evidence graph meet, this becomes a health invariant the research spine can gate on.

6 · Learning-loop safety

For ReasoningBank, skills and self-evolution: does a learned signal come from a verified outcome? A synthetic benchmark can plant a successful-but-wrong tool run and check that nothing strong is learned from it (F10).
